## Assessment vs. the Phase 0 estimate

`docs/recon.md` estimated Plan A Phase 2 at **3–4 weeks**. The measurement shows
the compile-closure strategy is larger than that estimate assumed:

- 1.36k source files, not "~50 Components files"
- 10.4k resource references, not "the emoji directory"
- ~206k lines of out-of-scope subsystems that still must compile

### Options going forward

**(A1) Copy everything needed to compile, then delete.**
Copy Telegram's full `main` source set + `res/`, get `:tgui` green, then delete
out-of-scope packages and re-green. Mechanical, huge diff, licensing audit over
thousands of files, but the "delete" step is straightforward and the compile
boundary is known.

**(A2) Compile-driven closure (what I actually did), then repair.**
Keep the 1,357-file closure, stub the 9 unresolved symbols, copy the referenced
`res/` subset. Fewer files than A1, but the *shown* closure is incomplete —
every out-of-scope package that compiled in the donor will throw errors here
(`Stories`/`Stars`/`Wallet` reference more of themselves than an import scan
proves). Expect several repair cycles.

**(A3) Narrow the seed: strip out-of-scope features from `ChatMessageCell` /
`DialogCell` *first*, then close.**
Edit the two entry files to remove Stories/Stars/Premium/Wallet/bots/IV/poll
paths, then re-run the closure. Smallest final module, but the edits are inside
`ChatMessageCell.java` (29.6k lines) and will be substantial and ongoing against
upstream. Directly contradicts "keep donor edits minimal".

## Honest status

- The module does **not** compile yet. Not attempted — no JDK or Android SDK on
  this machine (`java: command not found`, no SDK at the default path).
- Nothing here has been build-verified. Everything above is static analysis:
  file counts, import closure, `R` reference extraction.
- Per the brief's rule 6 ("never claim something works without running it"),
  **no compile-green claim is being made.**

## Recommendation

A1 (copy the whole donor source set, green it, then delete) is the lower-risk
path: the compile boundary is the donor's own build, so the first green build is
a known quantity rather than an open research problem. The cost is diff size and
a licensing audit over ~4k files, which `THIRD_PARTY.md` tooling can make
mechanical.

A3 produces the best final module but front-loads manual surgery into a 29.6k-line
file and makes upstream syncing painful — it trades maintenance cost for size.

**This is a scope/architecture decision (brief rule 8) and needs a human call.**
